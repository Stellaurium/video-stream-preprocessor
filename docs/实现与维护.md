# 预处理实现与维护

维护前读[用户流程](../使用说明.md)、[总维护约定](../AGENTS.md)。这是源码运行的PySide6桌面应用，Python3.11；保留独立`.venv`，运行依赖固定在`requirements.txt`。预处理使用带ArUco的`opencv-contrib-python`，不要和OCR环境合并。

## 代码地图

| 文件 | 职责与修改入口 |
| --- | --- |
| `app.py` | argparse、日志、QLockFile单实例、QApplication与主窗口 |
| `screenprep/gui.py` | 来源、选区冻结、四点/裁剪、撤销重做、时间轴、纯画面/全屏、预览计时 |
| `screenprep/geometry.py` | Pipeline、坐标校验、矩阵复合、有效区域、采样与配置兼容 |
| `screenprep/calibration.py` | 固定标准图生成、ArUco角点识别、单应矩阵拟合及误差 |
| `screenprep/media.py` | DirectShow/PyAV/FFmpeg采集、最新帧邮箱、Engine处理与seek |
| `screenprep/output.py` | 仅回环HTTP、最新NPY/PNG/JPEG、MJPEG及状态 |
| `screenprep/sdk.py` | 轻量NPY客户端，不依赖Qt/OpenCV |
| `screenprep/headless.py` | 无GUI处理入口，可复用同一Pipeline和输出服务 |

采集线程持续接收、只保留最新帧；处理与GUI显示各自取最新数据，慢消费者不积压历史画面。摄像头主要走OpenCV DirectShow；文件与网络流直接PyAV解码，FFmpeg还用于设备枚举及兼容路径。文件seek由解码线程执行，新请求覆盖尚未执行的旧请求。

## 几何与画质不变量

用户每次在当前结果上选点，Pipeline记录对应操作。矩阵按操作顺序左乘，最终从原始帧只重采样一次，避免重复插值。没有操作时返回输入；全部为整数裁剪时直接切片，不锐化。一般透视默认Lanczos4+0.2轻锐化；超采样只是历史对比候选，不是当前默认实现。

扩边必须保留有效区域遮罩，不能把之前裁掉的内容重新显露。输入尺寸变化需停止套用旧配置。手动四点需凸、顺序正确且在当前画面内；画布限制每边2–8192、最多1600万像素。

标准图1920×1080，ArUco字典DICT_4X4_50，四个ID为0–3，每标记四角共16个对应点；亚像素角点后用RANSAC拟合。它解决屏幕平面的透视关系，不是相机径向镜头内参标定。固定图可重复使用；识别后的日常画面不需要保留标记。

## 配置、日志与输出

`data/session.json`记忆来源；`autosave.json`恢复已应用操作；`calibration.json`是主动保存；重置备份在`reset-backup.json`。数据可能含用户输入路径，不能为了发源码把整个data打包上传。

接口/字段见[接口与配置](接口与配置.md)。服务默认只监听127.0.0.1，端口8765；本次没有增加公网发布、RTSP服务器或共享内存。

## 开发验证

项目根目录执行：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
.\.venv\Scripts\python.exe -m pytest -q
```

也可双击`tools/运行测试.cmd`。测试会生成临时小视频、模拟标定图及临时配置，覆盖几何、采样、取流、seek、GUI交互、预览帧率。首次缺测试依赖时先安装pytest，不把普通运行变成重新打包流程。

临时实验与真实素材联调脚本放在仓库外的测试目录，不是应用启动依赖。

## 入口与依赖恢复

根目录正常CMD和tools入口均按项目相对路径定位，保留独立Python环境。首次setup安装requirements.txt，开发测试依赖见requirements-dev.txt。摄像头枚举还需要bin中的FFmpeg或PATH里的FFmpeg。

当前只维护源码setup方式，旧PyInstaller构建脚本、spec和产物已从本仓库移除。data继续保存本机配置但不进入Git；固定标定图由GUI启动时生成到本机assets目录，Git只保留生成算法，不提交可重复生成的PNG/JSON。源码发布范围见[源码发布](源码发布.md)。
