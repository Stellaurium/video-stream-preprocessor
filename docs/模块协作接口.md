# 预处理与OCR模块协作约定

## 部署方式

两个应用独立启动，通过HTTP交接处理后的最新视频帧。当前默认本机`http://127.0.0.1:8765`，不需要共享内存、视频文件中转或模拟USB设备。

预处理服务只监听`127.0.0.1`。OCR客户端可以读远端HTTP，但跨电脑仍需另行实现/配置上游局域网发布与访问控制；当前不能把127.0.0.1改成另一台电脑地址就宣称服务已经公开可用。

## HTTP端点

| 路径 | 内容 | 建议用途 |
| --- | --- | --- |
| `/frame.npy` | NumPy NPY，`uint8`、`H×W×3`、BGR | 同机Python/OCR默认无损输入，加载时`allow_pickle=False` |
| `/frame.png` | 无损PNG，解码后BGR | 远端OCR默认无损输入、单帧检查 |
| `/stream.mjpg` | multipart MJPEG，JPEG质量95 | 浏览器/通用视频播放器预览，有损，不用于无损截图 |
| `/frame.jpg` | 当前JPEG | 预览用途 |
| `/status` | JSON状态 | 在线、序号、尺寸、帧率、最近帧年龄、处理与预览状态 |
| `/calibration.json` | 当前标定配置JSON | 重用几何关系，不包含输入地址 |
| `/` | 浏览器预览页 | 人工查看 |

帧头带`X-Sequence`、`X-Revision`、`X-Source-Seconds`、`X-Received-Monotonic`、`X-Width`、`X-Height`、`X-Pixel-Format=bgr24`。MJPEG每帧同样附带这些字段。

`revision`在几何配置变化时更新。尺寸、来源会话或revision变化后，下游清理旧选区并要求确认，不能沿用错误的ROI。输入断开时单帧返回503，MJPEG结束；无旧帧应被当作新截图保存。慢消费者取最新帧，不建立无限增长的帧队列。

单调时间戳只适合同机同一时钟域比较；跨电脑不能直接相减推断延迟。`source_seconds`是视频时间轴/连接后的相对时间，不是曝光时间；几何耗时不代表端到端摄像延迟。

## 坐标与无损截图

- 输入与处理图像均为BGR数组，尺寸描述使用`[width,height]`。
- 图像左上为原点，x向右、y向下。预处理矩阵为原始输入→最终输出，采用像素中心坐标。
- 裁剪ROI为`[x,y,width,height]`，Python半开切片`image[y:y+h,x:x+w]`。
- OCR框坐标属于对应`image.png`或补图自己的像素空间。加ROI偏移只能回到该题输入帧坐标；若要回到相机原图还需逆变换上游几何。
- GUI缩放、滚动与窗口大小只影响显示。保存使用锁定的原始输入帧，PNG无损；“无损”指不额外损失输入像素，不表示能恢复拍摄时已丢失的字迹。

## Python接入示例

在预处理项目根目录及其环境运行：

```python
from screenprep.sdk import FrameClient

client = FrameClient("http://127.0.0.1:8765")
for packet in client.frames(fps=15):
    image = packet.image
    # image: uint8 BGR，已校正、裁剪；自行处理，不应积压历史帧。
```

实体摄像头/采集卡可能被一个应用独占。让预处理或OBS单独占用物理输入，OCR再读取预处理HTTP或OBS虚拟摄像头，避免两套应用争抢设备。
